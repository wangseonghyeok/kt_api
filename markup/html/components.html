현재 HTML, include, SCSS, 공통 JS에서 실제 반복 사용되는 UI를 기준으로 Layout, Control, Feedback, Data, Domain 컴포넌트의 사용 기준과 유지보수 규칙을 정리했습니다.

System Guide

새 화면은 아래 계층을 기준으로 조립합니다. 기존 폴더 구조는 유지하고, 화면별 마크업을 만들기 전에 이 페이지의 공통 클래스와 include 조합을 먼저 확인합니다.

1. Foundation

색상, 간격, 서체, 아이콘, 상태 색상처럼 모든 UI가 공유하는 최소 단위입니다.

사용 기준
- 상태 색상은 kt-badge / kt-tag modifier 우선 사용
- 아이콘은 /assets/img/components 우선 사용
- 숨김 텍스트는 .blind 사용
- 스크롤 영역은 .kt-scrollbar 사용

2. Control

사용자가 직접 조작하는 버튼, 입력, 선택, 검색 UI입니다.

사용 기준
- button에는 type="button" 명시
- input 삭제는 data-clear_input + aria-controls 사용
- 비밀번호 토글은 data-password_toggle 사용
- 검색 자동완성은 data-prompt 구조 사용

3. Pattern

여러 control을 묶어 화면에서 반복되는 완성형 UI입니다.

사용 기준
- 페이지 상단은 .kt-page-header + .kt-path
- 하단 액션은 .kt-actions
- 목록은 kt-table / kt-data-table 계열
- 페이지 이동은 .kt-pagination 계열

4. Domain

Works, LDAP, Create Workspace, User처럼 특정 업무 화면에서 반복되는 조합입니다.

사용 기준
- include 조합은 상태별 화면에서 재사용
- 도메인 전용 class는 kt-works / kt-ldap / kt-newwork / kt-user prefix 유지
- JS 동작은 data-* hook으로 연결
- 디자인 수정 없이 상태와 데이터만 교체

Popup

공통 팝업은 버튼의 data-popup-url로 대상 HTML을 불러오고, data-popup-fragment에 지정한 모달 영역만 화면에 표시합니다. 팝업이 열려 있는 동안 바깥 페이지 스크롤은 잠기고, 닫으면 기존 스크롤 위치로 돌아갑니다.

Auth Popup Loader

  • 열기data-popup-open에 공통 팝업 ID를 지정합니다.
  • 불러오기data-popup-url에 같은 경로의 HTML 파일명을 넣습니다.
  • 추출 영역data-popup-fragment로 실제 표시할 영역을 지정합니다.
<button type="button"
    data-popup-open="#componentAuthPopup"
    data-popup-url="login-01.html"
    data-popup-fragment=".kt-auth-modal">
    login 01
</button>

<div class="popup kt-popup-loader" id="componentAuthPopup" role="dialog" aria-modal="true" aria-hidden="true" aria-label="인증 공통 팝업" hidden>
    <div class="kt-popup-loader__content" data-popup-content tabindex="-1"></div>
</div>
